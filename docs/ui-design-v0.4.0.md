## 조사에서 선택한 원칙

Apple은 Liquid Glass를 탐색과 조작을 위한 별도 계층으로 설명하고, 콘텐츠에 반복 적용하거나 과도하게 사용하면 계층 구분과 가독성이 나빠질 수 있다고 안내한다. 이 앱에서는 사이드바와 공통 실행 도구막대에 네이티브 재질을 사용하고, 수치와 상세 조절 영역에는 차분한 불투명 면을 사용한다. [Apple — Materials](https://developer.apple.com/design/human-interface-guidelines/materials)

SoundSource 6의 설계 회고는 조작 영역이 겹치는 슬라이더를 버린 과정, 간결한 기본 화면, 모서리와 안쪽 요소의 정합성을 강조한다. 이를 바탕으로 작은 앱에서 자주 만지는 항목을 먼저 보여 주고, 안내문은 도움말로 분리하며, 인접한 컨트롤 사이에 충분한 간격을 확보한다. 투명도 자체를 품질의 척도로 삼지 않는다. [Rogue Amoeba — SoundSource 6 Design Stories](https://weblog.rogueamoeba.com/2026/05/07/soundsource-6-design-stories/)

FabFilter Pro-Q 4는 중심 작업 영역과 상·하단 보조 기능을 구분하고, 선택한 대상에 필요한 조작을 가까이 배치한다. TimbreDock에는 이를 ‘대상과 실행 → 모델과 조절값 → 실제 세션 상태’의 구조로 적용한다. EQ 그래프를 모방하거나 측정되지 않은 시각화를 추가하지 않는다. [FabFilter — Pro-Q 4 Overview](https://www.fabfilter.com/help/pro-q/using/overview)

위 적용 방식은 공식 문서의 요구사항을 그대로 복제한 것이 아니라 TimbreDock의 사용 흐름에 맞춘 설계 판단이다.

## 구현 경계

- AppKit의 버튼, 팝업 메뉴, 세그먼트 선택과 접근성 역할을 유지하고 공통 표현 계층에서 그리기를 통일한다.
- 마우스 호버, 누름, 선택, 비활성, 키보드 포커스를 구분한다. 기본 컬러는 검정·흰색이며, Spatial의 위치와 신호 경로에는 의미를 가진 색을 사용한다.
- 밝은 모드·어두운 모드와 시스템의 투명도 줄이기·대비 증가를 고려한다. 움직임이 필요 없는 화면에 장식용 타이머나 애니메이션을 추가하지 않는다.
- 오디오 콜백, DSP, 장치 샘플레이트 변경 및 세션 교체 경로는 수정하지 않는다.

## 검정·흰색 대비와 Spatial 색상 보정

2026-09-22 후속 요청: 회색조가 강한 인상을 줄이고, TIDAL과 같은 검정·흰색 대비를 강조한다. Spatial에는 의미를 가진 색을 적용한다. [TIDAL 공식 제품 UI 자료](https://tidal.com/press)의 제품 이미지를 참고했으며, 해당 자료는 2021년 갱신본이므로 최신 데스크톱 UI 규격으로 취급하지 않는다. 구체적인 색과 명도는 사용자의 요청과 TimbreDock의 조작 구조에 맞춰 정했다.

- 큰 면은 거의 검정인 캔버스와 본문, 약간 밝은 내부 카드로 제한한다. 중간 회색의 넓은 배경을 줄인다.
- 선택한 모델·오버샘플링·프리셋과 Apply는 밝은 흰색 바탕에 검은 글자로 강조한다. 밝은 모드는 대비를 반전한다.
- 어두운 모드의 탐색·도구막대는 검은 캔버스 위의 clear Liquid Glass, 밝은 모드는 regular Liquid Glass를 쓴다. 창에 붙은 뒤 실제 모드에 맞는 틴트를 적용한다. 투명도 줄이기와 구형 OS의 기존 대체 경로는 유지한다.
- Spatial의 왼쪽 스피커는 청록, 오른쪽은 코랄, 청취자는 보라색이다. 각 오브젝트의 이름표·선택 링·좌표 안내가 같은 색을 공유한다.
- LL/LR 경로는 왼쪽 스피커의 청록, RL/RR 경로는 오른쪽의 코랄을 사용한다. 기존 실선·점선과 L/R/Listener 라벨도 유지해 색만으로 구분하지 않도록 한다.
- 2D와 3D는 같은 장면과 색상 정의를 공유한다. OFF 상태에서는 오브젝트와 경로를 어둡게 표시하되 저장된 배치를 알아볼 수 있게 한다.
- 변경 범위는 `GlassDesign.swift`, `SpatialUI.swift`의 표시 계층이다. 오디오 수치·DSP·장치 전환과 종료 오류를 수정한 `StudioChoiceContainer`의 크기 계산은 유지한다.

## 1차 UI 재정비 검증

검증 빌드는 `52f7454-dirty · 2026-09-22T06:29:35Z`이며, macOS 27 / Apple Silicon에서 확인했다. 기존 0.4.0 작업이 포함된 `codex/timbredock-redesign`의 로컬 빌드다.

### 실행 중 종료 오류 수정

개발 중 새 Spatial 선택 컨트롤에서 SwiftUI와 AppKit의 크기 계산이 서로를 다시 호출하면서 `NSGenericException`이 발생했다. `NSSegmentedControl`의 너비 갱신이 다시 고유 크기와 창 제약조건 계산을 유발한 것이 원인이었다. 이 문제는 이번 UI 변경에서 발생했다.

`StudioChoice`가 일반 `NSView` 컨테이너를 반환하게 하고, SwiftUI에 제공할 크기를 명시적으로 계산하도록 수정했다. 컨테이너는 내부 컨트롤을 수동 배치하며, 세그먼트 너비는 실제 차이가 있을 때만 갱신한다. 수정 후 실제 앱을 다시 열어 다섯 페이지와 Spatial 2D/3D·청취자 선택을 확인했다. 15:35 KST 확인 시 실행 중이었고, 마지막 종료 보고서는 수정 전인 15:14:09 KST였다.

실제 앱 조작은 어두운 모드에서 확인했다. 최소 창 크기와 밝은 모드 검증은 자동 레이아웃 검사 및 렌더링 결과에 근거한다. 렌더링 이미지는 Metal/SceneKit 합성을 완전히 재현하지 않으므로 Spatial의 실제 화면은 별도 실행 화면으로 확인했다.

실제 장치에서의 음악 재생·PCM 2× 전환·청취 비교, VoiceOver 음성 출력, Instruments 성능 측정, 이전 macOS의 재질 대체 경로는 이번 변경에서 재검증하지 않았다.
